# Spec Template — 统一 Spec 模板

> 版本: 2.0.0 | 更新: 2026-06-07
> 10 个标准区块，按工作流裁剪

## 模板

```markdown
# Spec: {任务标题}

> 工作流: {light|riper-one|super-dev}
> 任务ID: {T-XXXX}
> 创建时间: {ISO8601}

## 1. 需求摘要
- 目标：{一句话描述}
- 范围：{做什么/不做什么}
- 验收标准：{可测试的条件列表}

## 2. 影响分析
- 涉及文件：{文件列表}
- 涉及模块：{模块列表}
- 数据库变更：{DDL/DML/无}
- 外部依赖：{API/RPC/消息队列}

## 3. 接口契约
- API 端点：{方法 + 路径 + 参数 + 响应}
- RPC 接口：{服务 + 方法 + 参数}
- 数据模型：{实体定义}

## 4. 实现方案
- 技术选型：{框架/库/工具}
- 核心逻辑：{伪代码或流程图}
- 边界处理：{异常/超时/并发}

## 5. 测试策略
- 单元测试：{覆盖范围}
- 集成测试：{场景列表}
- 边界用例：{列表}

## 6. 安全考量
- 输入验证：{规则}
- 权限检查：{角色/资源}
- 敏感数据：{处理方式}

## 7. 回滚方案
- 回滚步骤：{具体操作}
- 数据兼容：{向前/向后兼容}

## 8. 施工交接说明
- 执行顺序：{步骤1→步骤2→步骤3}
- 关键文件：{需要先阅读的文件列表}
- 已知约束：{不能做的事}
- 参考范例：{类似功能的代码位置}

## 9. 机器可执行验收
- [ ] 编译通过: `mvn compile -pl {module}`
- [ ] 测试通过: `mvn test -pl {module}`
- [ ] 文件存在: `test -f {path/to/file}`
- [ ] 内容检查: `grep -q "{pattern}" {file}`
- [ ] 写入范围: `git diff --name-only` 全部在 allowed_paths 内

## 10. 任务分解
- [ ] 子任务 1：{描述} [{估时}]
- [ ] 子任务 2：{描述} [{估时}]
```

## 按工作流裁剪

| 区块 | light | riper-one | super-dev |
|------|-------|-----------|-----------|
| 1. 需求摘要 | **必填** | **必填** | **必填** |
| 2. 影响分析 | 简化 | **必填** | **必填** |
| 3. 接口契约 | 可选 | **必填** | **必填** |
| 4. 实现方案 | 简化 | **必填** | **必填** |
| 5. 测试策略 | 可选 | **必填** | **必填** |
| 6. 安全考量 | 跳过 | 简化 | **必填** |
| 7. 回滚方案 | 跳过 | 简化 | **必填** |
| 8. 施工交接说明 | 跳过 | **必填** | **必填** |
| 9. 机器可执行验收 | 简化 | **必填** | **必填** |
| 10. 任务分解 | 可选 | **必填** | **必填** |

## 验收标准编写规范

验收标准必须是**可测试的**，每个标准对应一个或多个机器可执行检查：

| 验收标准 | 机器检查 |
|----------|----------|
| "接口返回 200" | `curl -s -o /dev/null -w "%{http_code}" http://localhost:8080/api/xxx` |
| "金额精度正确" | `grep -q "BigDecimal" Service.java` |
| "无 SQL 注入" | `python skills/harness-quality/scripts/tier1/check-sql-injection.py` |
| "写入范围合规" | `bash skills/harness-quality/scripts/tier0/check-write-paths.sh` |
